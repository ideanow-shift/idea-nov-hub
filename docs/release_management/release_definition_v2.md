# Release Definition v2: 業務運用開始基準

## 変更

IDEA NOV PlatformのReleaseは、コードが完成した時点ではなく、対象業務を安全に開始できる時点で判定する。

Release Readyは、以下の5条件が**すべてPASS**の場合だけ成立する。1件でも未確認、条件付き、またはFAILがあればRelease Readyではない。

| 条件 | PASSの意味 | FAILまたは未確認の例 |
| --- | --- | --- |
| 1. データ整合性 | 対象データの正本、期間、品質、同期状態が目的に対して確認済み | NOV Talentの対象データが未投入・隔離中・未照合 |
| 2. 業務フロー | 誰が何を開始・確認・承認・例外処理するか運用可能 | 担当者、承認経路、例外時の連絡先が未決定 |
| 3. UI/UX | 実務者が誤解なく主要操作を完了できる | 未接続を稼働中に見せる、必須操作が到達不能 |
| 4. 実運用レビュー | 対象部門が実データに近い条件で受入確認した | Store Operationsの営業部レビューが未実施/不合格 |
| 5. 開発品質 | テスト、セキュリティ、変更範囲、rollbackが確認済み | 必須テスト不合格、機微情報露出、rollback不能 |

## 判定状態

```text
NOT_READY: 5条件のいずれかが未確認
CONDITIONAL: 5条件中に条件付き/期限付きの項目がある
NO_GO: 5条件のいずれかがFAIL、または安全境界に違反
RELEASE_READY: 5条件すべてPASS、承認記録あり
RELEASED: RELEASE_READY後に、別途承認済みの公開・運用開始が完了
```

`CONDITIONAL`はRelease Readyではない。表示・検証・社内限定の準備状態として扱い、利用部門へ正式運用開始を案内しない。

## 領域別の最低例

| 領域 | 運用開始に必要な追加確認 |
| --- | --- |
| NOV HUB | 利用者が必要な業務へ到達でき、未接続カードが準備中として明示される |
| Store Operations | 営業部が対象KPI、対象月、CSV/正式APIの扱い、例外時の導線を確認済み |
| NOV Talent | 対象学年・取込データ・隔離/確認フロー・編集権限が業務目的に沿って確認済み |
| Core DB | SSoT/UUIDの事実、read-only境界、証跡・責任者が目的に応じ確認済み |
| Accounting Core | 正式利益source、確定期間、未確定表示、経理責任者の受入が確認済み |

## 非該当

設計資料、ローカル試作、static UI、未接続のplaceholder、テストだけのPASSは、単独ではRelease Readyを意味しない。
