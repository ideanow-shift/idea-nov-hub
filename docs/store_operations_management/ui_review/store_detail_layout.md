# 店舗詳細表示仕様

## 認可境界

店舗詳細はServerが解決した`employee_store_assignments`の有効範囲、または全アクティブ店舗を許可された利用者の範囲だけを表示する。scope外店舗URLは403「対象店舗の閲覧権限なし」とする。URL、店舗ID、frontend Role claimによる拡張を認めない。

AM・店長のprimary／secondary／兼任は同じassignment relationで扱う。employeeのprimary storeを第二正本にしない。応援勤務は売上・生産性・稼働スタッフ数の集計に利用しても、閲覧Scopeを増やさない。

## 共通上部

1. 一覧へ戻る
2. 店舗名、店舗状態、対象月、許可された利益状態
3. 1〜2文の結論
4. 今月の最優先課題
5. 次に確認すること
6. 主要KPI要約

優先アクションから遷移した場合、関連区分と対象KPIの文脈を残す。

## 4区分

### サマリー

総売上、許可された利益／状態、総客数、総単価、総リピート率、総生産性、現在の課題。利益Data Scopeがなければ利益項目を非表示にする。

### 売上・利益

総売上→店舗売上（技術、通常店販、MID）＋EC按分→利益の順。直営店舗かつ利益閲覧許可時だけ確定利益・利益率を表示する。FC利益は「V1対象外」とし、構造上自然なら利益領域を非表示にする。

### 顧客・リピート

総客数を主に、新規／既存を内訳とする。総リピート率を主に、新規／再来／固定を展開する。

### 価値・生産性

総単価、総生産性を主に、技術単価、店販売上、店販購買率を補助とする。「稼働スタッフ数 ○人相当」の算出には応援勤務を含められるが、それを閲覧権限の根拠にしない。

## 状態分離

利益未確定は集計中、機能未準備は準備中、FC利益はV1対象外、Data Scope外は項目非表示、API未接続は503「接続準備中」とする。相互に置き換えない。詳細は[利益・Failure状態](profit_status_layout.md)を参照する。

戻る際は一覧状態を復元する。店長にはassignment外店舗への導線や許可集合を拡張するFilterを表示しない。
