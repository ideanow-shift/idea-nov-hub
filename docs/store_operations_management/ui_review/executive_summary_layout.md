# Executive Summary表示仕様

## 目的

5〜10秒で「対象範囲の状態」「要対応数」「次に優先するテーマ」を理解させる。数字の羅列ではなく結論を先に置く。

## 表示順

1. 対象月、月次／年間累計、全店／直営／FC
2. 1〜2文の結論
3. 総売上（税抜）、利益／利益状態、要対応店舗数
4. 好調／安定／改善中／要対応の件数
5. データ反映店舗数、最終更新

## 結論文

PCは最大2行、スマートフォンは最大3行を目安にする。値が取得できない領域は断定せず、利用できる根拠だけで文章を構成する。

例: 「直営○店舗のうち2店舗が要対応です。売上より、新規リピート率の低下を優先して確認してください。」店舗数は表示時点の許可済み・有効店舗から算出する。

## 主数値

| 項目 | 主表示 | 補助 |
| --- | --- | --- |
| 総売上（税抜） | 月次値 | 予算比、前年同月比、年間累計 |
| 利益 | 権限範囲内の直営店確定値または状態 | 利益対象店舗数、確定対象月、確定予定 |
| 要対応店舗数 | 件数 | 対象Scopeの総店舗数 |

総客数、総単価、リピート率、生産性はここで大きく重複表示しない。

## Filter連動

全店／直営／FCはServerが返した許可済み店舗ID集合を狭める表示Filterである。変更すると結論、件数、主数値、状態分布、反映店舗数を更新するが、許可集合を拡張しない。権限外Scopeは選択肢として表示せず、0件でも他Scopeへ自動切替しない。

全店Filterでは「全店利益」を使わず、「直営店利益（対象○店舗）」と「FC店舗利益はV1対象外」を表示する。売上対象店舗数と利益対象店舗数を分ける。直営Filterでは「直営店利益」、FC Filterでは「利益 V1対象外」とする。

## 状態

- 集計中: 利益の位置へ「集計中」と確定予定を表示
- 準備中: 領域を維持し「準備中」と理由を表示
- データなし: 「対象条件の店舗データはありません」＋条件変更導線
- 通信エラー: Summary全体を値なしにし、再試行を表示

権限なし、V1対象外、API未接続、Previewを集計中／準備中へ置換しない。正本は[利益・Failure状態](profit_status_layout.md)を参照する。
