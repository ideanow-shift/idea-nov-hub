# Dashboard全体分析

## 判定

現行案は、Role別Scope、月次Projection、データ状態、店舗詳細4区分、モバイルカード化という基礎が揃っている。一方、Executive Dashboardは数値の把握が先行し、「どこへ時間を使うか」への到達が遅い。V1では構成要素を増やさず、閲覧順を次へ固定する。

1. Executive Summaryで全体の結論を読む
2. 優先アクション最大3件から最優先店舗を選ぶ
3. 業績ドライバーで原因候補を確認する
4. 店舗ポートフォリオで状態を絞る
5. 店舗一覧から2操作以内で詳細へ移る
6. 店舗詳細で最初に確認することを決める

## 現状評価

リポジトリ内のPhase 5基準画像とレビュー記録を確認した。PCは大きな数値、広い余白、Accounting metadataにより総額と更新時点を見つけやすい。店舗詳細は「今月やること」がKPIより先にあり、判断目的が明確である。

改善余地は、Executive Summaryが数値中心で結論文が弱いこと、スマートフォンで優先アクションまで遠いこと、業績ドライバーが長く店舗一覧を押し下げること、店舗状態と利益状態の意味が近く見えることである。詳細は[現在案の問題](ui_problems.md)を参照する。

## 意思決定時間の評価

| 目標 | 現状見込み | 再設計後の目標 | 評価方法 |
| --- | --- | --- | --- |
| 全体状態 | PC 10秒以内、Mobileは条件付き | 5〜10秒 | Summaryを読んで状態を一文で回答 |
| 要対応店舗数 | 10秒程度 | 10秒以内 | 件数と対象Scopeを回答 |
| 最優先店舗 | 30秒超の恐れ | 30秒以内 | 優先アクション1位を回答 |
| 問題KPI | 情報量次第で60秒超 | 60秒以内 | 1位カードからKPIと差分を回答 |
| 店舗詳細 | 一覧またはカードから到達可能 | 2操作以内 | カード／行→詳細 |
| 店舗で確認すること | 詳細では良好 | 5分以内 | 結論と「次に確認」を回答 |
| 利益状態 | metadataで確認可能 | 15秒以内 | 対象月、確定／集計中／準備中を回答 |

## 維持する画面関係

Dashboardと店舗詳細の2階層を維持する。新しい第一階層ページは作らない。優先アクション、店舗一覧、店舗詳細から同じ店舗へ遷移し、戻ると対象月、集計軸、範囲、状態、並び順、列、スクロール位置を復元する。
