# V1 Scope Boundary

## V1で扱うもの

- 月次、予算比、前年同月比、年間累計、月別推移
- Executive Summary、優先アクション最大3件、業績ドライバー4群
- 店舗ポートフォリオ、店舗一覧、店舗詳細4区分
- 総売上（税込）、利益／利益状態、客数、単価、店販、リピート率、生産性
- 技術売上、通常店販売上、MID売上、EC按分売上の誤解のない内訳
- 取得済み、集計中、準備中
- Role別初期表示と既存Permission／Store Scope
- PC、タブレット、スマートフォン
- 短い判断支援文。AIを独立機能として強調しない

## V1で扱わないもの

- 日別売上、日次進捗、リアルタイム、POS、顧客単位データ
- スタッフ個人分析、スタッフ別売上、個人ランキング
- 単純な売上／利益ランキング、健康スコア表示
- アクション履歴、通知、承認、入力、書き込み
- 新しいPermission、Store Scope、Data Scope、Action Scope

## V2以降

月末着地予測、施策効果測定、異常値自動検知、高度な差異分解、店舗ベンチマーク、保存済み表示、カスタムDashboard、高度な通知、会話型AIをV2候補とする。V1デザインへ先取りしない。

## 確定資料との競合処理

[Monthly Projection Contract](../monthly_data_foundation/monthly-projection-contract.md)は当時、客数・単価をSource Scope外としている。一方、今回の確定V1指示は顧客・単価・リピート・生産性をUI対象に含める。指示の優先順位に従い画面領域は設計するが、Contract未承認項目は値を創作せず「準備中」とする。実装前にData Contract Ownerの承認が必要である。

同資料ではECを店舗へ未配賦としているが、今回指示ではEC按分売上を店舗詳細対象とする。按分Contractが承認されるまで、EC按分は「準備中」で表示領域だけ維持する。

## 巻き戻し防止

- 未取得を0へ変換しない
- FC利益制約をUI都合で解除しない
- Scope外店舗を空データとして見せない
- UIで状態判定式、Permission、優先順位ロジックを固定しない
- Headquarters配賦を店舗値へ混入しない
