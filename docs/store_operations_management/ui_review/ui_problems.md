# 現在案の問題

## P0問題

| 問題 | 影響 | 改善方向 |
| --- | --- | --- |
| Executive Summaryが総額中心で、全体結論と優先テーマが弱い | 数字は読めても次の行動が決まらない | 1〜2文の結論を主役にする |
| Instruction上のV1と既存Data Contractに客数・単価・EC按分の差がある | 準備中と確定値の混在リスク | 実装前にContractを承認し、未承認は準備中 |
| 店舗状態の判定根拠が画面から追えない | 評価・序列と受け取られ、信頼を失う | 状態理由と関連KPIへ到達可能にする |
| 優先アクションの根拠と鮮度が不明だと一般論に見える | 営業部が無視する | 現在値、比較差、影響度、次に確認を同じカードに置く |

## 情報過多・重複

- Executive Summaryへ主KPI以外を大きく並べると、優先アクションが下がる
- 業績ドライバーを全展開すると、スマートフォンで店舗一覧へ到達しにくい
- Total Repeatなど同じKPIを複数群へ出すと原因構造が曖昧になる
- 優先アクションと店舗詳細の「今月の重点」が同じ文章だと役割が重複する
- 準備中項目を1件ずつカード化すると、取得できない情報が主役になる

## デバイス別問題

- 1366pxで全列を表示すると文字と数値が小さくなり、比較性能を失う
- タブレットでホバー説明に依存すると巡回時に意味を確認できない
- スマートフォンでPC順を縮小すると縦長になり、優先アクションが遠い
- モバイルの長いTab名、Filter、KPI群は横スクロールや誤タップを招く

## 感情・運用上の問題

店舗状態が人や店舗の評価に見えること、月次データが毎日変わらないこと、利益確定が翌月になることが継続利用の障壁である。数字を監視する画面ではなく、確認順を支援する画面であることを、文言と状態理由で伝える必要がある。
